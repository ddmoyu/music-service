# 酷我会员账号音质复测

日期：2026-10-23；Windows；生产代码基线为当前工作区 0.1.8。本轮只做账号与协议、真实音频对照，未修改生产适配器，也未新增 Cookie profile 或 Hi-Res 支持。

后续实现状态：用户确认后，kuwo-native 0.1.9 已完成黑胶与原生尾部处理，见[黑胶接入验收](kuwo-vinyl-acceptance.md)。本文保留当时的协议探测结果；下文“尚未接入”描述探测当时状态。

**结论：新 Cookie 有效，账号为豪华 VIP。现有三档的首轮对照未见 Cookie 带来音质差异；随后对梅艳芳《亲密爱人（黑胶版）》发现了单独的 `vinyl` 档位，完整下载并验证了 24 bit／96 kHz FLAC。匿名与会员的该档位文件也完全相同，提升来自选择了不同音源档位，不能归因为会员 Cookie。黑胶档位仍未接入生产适配器。**

## 账号与会员证据

用户最初提供的 Cookie 与本轮浏览器请求对应不同账号。首次复查仍为非会员的结果属于旧账号，不作为本轮会员测试结论。收到新 Cookie 后，所有会员组均重新请求。

新 Cookie 保存在 `.local-secrets/kuwo-cookie.txt`，旧值仅在同一忽略目录内留作本地备份；两者都不会进入 Git。原始账号／会员响应及带签名的音源地址仅存放在 Git 忽略的 `out/kuwo-svip-verified/`。本文不记录账号、订单、Cookie 或签名。

| 检查 | 实测结果 |
| --- | --- |
| 登录会话 | `sysinfo?op=gui` 返回与新 Cookie 相符的账号资料 |
| 用户提供的会员查询 | `GET /vip/v2/user/vip?op=gmb` 返回生效产品 `VIP_luxury`、`VIP1`、`VIP4` |
| 有效期 | **2026-11-23 11:15:18（北京时间）**，与用户提供的到期日期一致 |
| 权益字段复核 | `POST /vip/v2/user/vip` 的只读 `op=ui`：`vipLuxuryExpire`、`vipExpire`、`vipmExpire` 均在有效期内 |
| SVIP 字段 | 同一查询的 `svipExpire` 为 0；接口标识为豪华 VIP，用户随后确认是豪华 VIP，不是超级 VIP |

## 现有音源接口对照

使用当前 C++ 适配器对应的 `mobi.kuwo.cn/mobi.s?type=convert_url_with_sign`，两组参数相同，仅解析请求的账号 Cookie 不同；CDN 读取不携带账号 Cookie。每个成功地址读取前 65,536 字节，核验 MP3 帧头或 FLAC STREAMINFO，并比较服务器声明的完整大小。

| 歌曲 | 标准请求 | 高品质请求 | 无损请求 | 会员与匿名差异 |
| --- | --- | --- | --- | --- |
| 周杰伦《晴天》228908 | MP3 128 kbps／44.1 kHz | MP3 320 kbps／44.1 kHz | FLAC 24 bit／44.1 kHz | 未发现；前缀哈希和文件大小相同 |
| 《恒星不忘 Forever Forever》661608480 | MP3 128 kbps／44.1 kHz | MP3 320 kbps／44.1 kHz | FLAC 24 bit／48 kHz | 未发现；前缀哈希和文件大小相同 |
| 蓝心羽《晴天》78932517 | MP3 128 kbps／44.1 kHz | 返回 MGG，未验证为可用目标品质 | 返回 MGG，未验证为可用目标品质 | 未发现；前缀哈希和文件大小相同 |

共 **3 首 × 3 档 × 2 组＝18 次解析与音频前缀读取**。9 组 A/B 对照均相同。不能根据上游 `bitrate=2000` 或 `bitrate=24000` 等协议值直接推断实际码率、位深或 Hi-Res。

对周杰伦《晴天》的两组 FLAC 另行完整读取：均为 **55,397,039 字节、24 bit／44,100 Hz／双声道、269,747 ms**，完整 SHA-256 均为：

```text
45d2073bbe60910d87e77f9f5eb87951b36a24a7da1492c7f0e7a3d5e7dd38c2
```

这组完整文件逐字节一致，并与此前非 VIP 对照的原始 FLAC 哈希一致。

## 扩展档位与账号参数

以下是参数兼容探测，不是已确认的官方档位声明；只报告返回文件事实，不按请求名称标注音质。两首样本、三种参数均分别测试匿名与会员。

| 请求参数 | 周杰伦《晴天》 | 《恒星不忘》 | Cookie 的影响 |
| --- | --- | --- | --- |
| `br=4000kflac` | 实际降为 MP3 128 kbps | 返回 MFLAC，34,310,509 字节 | 两组相同 |
| `br=20000kzp` | 仍为 FLAC 24 bit／44.1 kHz | 仍为 FLAC 24 bit／48 kHz | 两组相同 |
| `br=20900kmflac` | 返回 MFLAC，186,980,254 字节 | 返回 MFLAC，207,583,327 字节 | 前缀哈希及服务器声明大小相同 |

MFLAC／MGG 只验证了地址可读、前缀与声明大小；未完整下载、未解密、未核验实际采样率／位深或可播放性。文件更大不等于已验证音质更高。

另外核对官网 `/api/v1/www/music/playUrl`：周杰伦《晴天》匿名与会员均返回业务码 -1，没有音源；《恒星不忘》两组均为 320 kbps MP3，蓝心羽《晴天》两组均为 128 kbps MP3。继续对 228908 显式携带 `uid/sid`、`loginUid/loginSid` 两种参数组合，mobi 仍返回相同 FLAC，网页播放接口仍无音源。会话可用、会员已生效，并不代表每条音源协议已经正确消费该权益。

## 首轮判断与后续技术缺口

- 首轮样本在当前实现中的最高结果仍为既有 FLAC，无新增可用档位；保持原有品质声明和严格校验。随后指定歌曲的独立协议发现见下节。
- 如果继续研究更高档位，需要核实官方客户端实际使用的会员取流与授权参数，并为目标专有格式实现原生处理和实际音频验证，不能只附加 Cookie 或改一个 br 值就标记支持。
- 本轮没有改变账号、购买、续费或下载配额设置，没有执行第三方下载／解密工具。Python 仅驱动 HTTP 和读取字节，Node 只生成官网已有的请求校验头；生产代码不依赖这些探测脚本。

本地证据：`out/kuwo-svip-verified/summary.json`、`audio-comparison.json`、`web-play-comparison.json`、`extended-quality.json`、`auth-parameter-check.json`、`full-flac-comparison.json`。旧账号的本轮初查存于 `out/kuwo-svip-probe/`，与新账号证据分开。

## 指定歌曲：梅艳芳《亲密爱人（黑胶版）》

同日根据用户指定歌曲追加测试。原生服务搜索 `亲密爱人（黑胶版）` 和 `亲密爱人 黑胶版` 均返回精确版本：歌曲 ID `492445332`，歌手梅艳芳，专辑《亲密爱人（黑胶版）》、专辑 ID `46894897`，曲号 3。详情通过 JSON API 复核，音频实际时长约 **296.630 秒**。

### 三档生产下载与额外黑胶音源

| 档位 | 实际格式与规格 | 本地成品大小 | 完整下载与解码 | 生产实现状态 |
| --- | --- | --- | --- | --- |
| 标准 | MP3 128 kbps／44.1 kHz／双声道 | 4,828,276 字节，约 4.60 MiB | 通过 | 原生服务 `standard`，严格品质策略 |
| 高品质 | MP3 320 kbps／44.1 kHz／双声道 | 11,949,047 字节，约 11.40 MiB | 通过 | 原生服务 `high`，严格品质策略 |
| 普通无损 | FLAC 16 bit／44.1 kHz／双声道 | 32,331,375 字节，约 30.83 MiB | 通过，PCM 校验匹配 | 原生服务 `lossless`，严格品质策略 |
| 黑胶 `vinyl` | FLAC **24 bit／96 kHz／双声道** | 112,571,364 字节，约 107.36 MiB | 移除源文件附加尾部后通过，PCM 校验匹配 | 仅独立协议测试，尚未接入服务品质选项 |

前三档通过当前 C++ 服务建立任务、下载、发布并使用文件票据完整读取；标题、歌手、专辑、曲号和封面均写入。歌词上游不可用，任务按 `best_effort` 明确报告 `unavailable`。这些成品包含服务写入的元数据，大小不应直接与未处理的 CDN 源文件比较。

搜索接口的 `MINFO` 仅列出普通无损等档位，但 `N_MINFO` 还声明了 `level:vinyl,bitrate:23000,format:flac,size:107.36Mb`。按照该声明使用 `br=23000kflac`，两组都返回同一歌曲 ID、`type=0` 和 FLAC；实际 STREAMINFO 与独立解析结果均为 24 bit／96 kHz。`23000` 是上游档位参数，不是实际 23,000 kbps 音频码率。

### 豪华 VIP 是否造成提升

对该歌曲的三个普通档位及黑胶档位均执行匿名／豪华 VIP 对照，解析参数一致，仅取流请求是否携带账号 Cookie 不同，CDN 请求不发送账号 Cookie。四组的前 65,536 字节哈希和完整大小均相同。

对普通无损和黑胶档位分别完整读取两组源文件，结果如下：

| 档位 | 两组完整源文件大小 | 两组完整 SHA-256 | 结论 |
| --- | --- | --- | --- |
| 普通无损 | 32,255,573 字节 | `6b0c4fc49ccbffef72c7cb2f7163fbd8b82161e0b26f993267486044375218cf` | 逐字节一致 |
| 黑胶 | 112,571,394 字节 | `728c1627ff7be77cd98a5074786966534e44b3e85b3def4c629e92fc547b9e7c` | 逐字节一致 |

因此，这首歌可以获得比当前普通无损更高的**文件规格**；本次结果并非豪华 VIP Cookie 独有。不能把单首歌、单个接口的结果扩展为所有歌曲的会员权限结论，也没有据此认证原始母带的制作规格。

### 黑胶文件尾部与无损校验

上游黑胶源文件可以解出全部 PCM，解码后的 MD5 与 STREAMINFO 的 `874082e3f1a569fe2f568d5a659c1423` 一致，但严格解码末尾报 `invalid sync code`／`invalid frame header`。末帧 CRC16 检查定位到有效帧结束偏移 **112,571,364**，其后附加 **30 字节**。

保留原始文件，另生成只移除这 30 字节的本地副本；没有转码、重采样或修改音频帧。副本再次完整解码，退出码为 0、无诊断，PCM MD5 与源文件一致；副本 SHA-256 为 `9067f310472ec98276765b133977bf84b97a1a97b49a87b0ad7686c5ccab6790`。不能把本例的“减去 30 字节”直接推广为生产规则，其他资源需按实际帧边界和音频校验处理。

下载与探测脚本位于 Git 忽略的 `out/`；`ffprobe`／`ffmpeg` 仅用作本轮独立文件解析、完整解码和 PCM 校验，没有替代生产下载实现，也没有引入生产依赖。此次未修改生产代码。

本地成品：`out/kuwo-qinmi/梅艳芳 - 亲密爱人（黑胶版）-黑胶24bit96kHz-可播放.flac`。普通三档和原始黑胶文件同目录保留。证据为该目录中的 `search-summary.json`、`quality-report.json`、`verification.json`、`source-quality-declarations.json`、`vinyl-comparison.json`、`vinyl-tail-inspection.json`、`vinyl-full-verification.json`。Cookie、签名音源响应、音频和脚本均不进入 Git。
