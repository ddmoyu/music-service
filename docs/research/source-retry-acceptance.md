# 严格换源真实音源验收

日期：2026-10-26；Windows x64，MSVC Debug，原生服务 0.1.30，SQLite schema 8。

结论：两首真实歌曲均取得了成功的自动换源下载与显式试听换源样本；成功率排序、统计持久化及文件重启回读已验证。重复测试存在真实上游超时及原始身份未取得时的下载失败，**不将本轮记录表述为全量通过或稳定性验收完成**。

## 环境与方法

- 启动独立临时服务和新数据目录，保留默认启用的平台；不导入 Cookie，不改动现有客户端、账号或服务数据。
- 客户端使用 Python 标准库调用后端 HTTP API；搜索、详情、音源解析、CDN 取流、MP3 校验和发布都由项目原生代码完成，没有新增工具或依赖。
- 下载请求为 standard、strict、allow_preview=false、metadata_policy=skip，单文件上限 32 MiB；单次下载预算 90 秒、绝对预算 240 秒。试听使用默认 10 秒目录总预算。
- 先验证原平台解析失败，再显式调用试听 switch-source；下载只创建原平台任务，换源由后台执行。
- 完整读取试听流和发布文件，按流计算 SHA-256；发布文件的客户端完整读取与服务本地文件大小、哈希一致。重启后再次读取文件并核对统计。
- 这验证了后端真实音频字节传输与下载校验，没有运行浏览器播放器、声卡播放或人工听辨。

## 失败与边界：保留第 03／04 轮记录

1. 第 03 轮《江南》试听换源成功后，Range 读取返回 504；随后的完整读取成功。后台的短音频头探测不能保证后续每次媒体请求成功，前端仍须处理播放错误并显式请求换源。
2. 第 04 轮《江南》下载在第 1 次尝试失败，最终错误为 CREDENTIALS_REQUIRED，详情为 `original title and artists are unavailable`。后台未取得可用于严格匹配的原始身份，因此拒绝猜测换源。该任务没有保存原始详情查询的具体失败原因，不能仅凭此记录确定是网络超时、限流还是其他上游错误。
3. 第 04 轮《美人鱼》试听换源耗尽默认 10 秒总预算，返回 504 REQUEST_DEADLINE_EXCEEDED 和已尝试平台；同轮自动下载仍完成酷我换源。若前端继续尝试，应保留最初 track 并累计错误 details 内的 attempted_sources。
4. 第 04 轮再次显式切换《江南》，排除先前所有尝试平台后返回 422 SOURCE_EXHAUSTED，并保留排除列表。没有回到已尝试平台，也没有降低歌名／歌手／时长要求。

第 03 轮另外记录了 1 次详情请求 UPSTREAM_TIMEOUT，客户端在最多 3 次 GET 尝试内恢复；原源解析、换源 API 和下载任务没有被客户端静默重试为成功。

脚本初版曾错误读取文件描述中不存在的 sha256 字段，以及假定失败结果一定含 actual_identity；它们导致报告阶段异常，已修正。还补齐了 Range 成功条件与失败结果复核。原始 report.json 保留当时状态，**verification.json 是对已捕获响应的最终复核**：第 03 轮 31 条检查中 30 条通过，未通过项为《江南》Range；第 04 轮 22 条中 18 条通过，4 条未通过检查对应上述下载和试听两个失败场景。未反复运行直至得到全绿结果，也未放宽匹配或请求预算。
