# 参考项目功能补齐计划

日期：2026-10-22。状态：**A～E 已完成已批准范围；G14 NCM 本地导入和 G16 独立歌词／封面已在 0.1.6 完成本机验收并随 `e13053c` 提交。G09 网易云扫码登录明确不做。第 14 节记录本轮三平台补齐的验收；用户随后要求 Windows 优先、引入新的音乐平台，后续范围与顺序转入[平台路线图](platform-roadmap.md#当前执行顺序与交付范围)，非 Windows 专门验收排到最后。**

本计划回答每项缺失功能做什么、依赖什么、如何验收，以及哪些功能暂不进入首批。按推荐项 D1～D3 执行；阶段批准不等于授权提交或发布。

- 相较 music-lib，QQ、酷狗、咪咕、千千、Jamendo、Bilibili 尚未接入；Apple Music 在现有任务清单中明确排除，需要另作范围决策。

## 2. 实施边界与契约

1. 延续纯 C++20 后端。平台协议、签名、请求、下载与必要解密原生实现，不调用其他语言 SDK、外部下载／签名／转码程序或第三方解析服务。不把参考项目的 CLI／GUI 移植进服务。
2. 新平台沿用 Provider 注册、公共上游入场和通用任务，不为每个平台增加独立队列、数据库或通用路由条件分支。
3. 延续 `standard/high/lossless/hires`、`strict/allow_lower`、`allow_preview`。默认仍为 standard、strict、不允许试听；没有证据的品质／完整性保持未知，不能用 FLAC 后缀或接口参数代替实际验证。
4. 新增公开字段采用兼容性扩展。新增授权会话、播客实体等契约先写入现有 API／模型设计再实现；本草案中的概念不是已经存在的 HTTP 接口。
5. 影响产物的标签、歌词选择、命名、目录与侧文件配置进入规范下载意图及配置版本；完成结果复用须核验新要求。已接受任务使用受理时的配置快照，幂等重放返回原结果，不因后来修改默认配置而改变。
6. **集合下载沿用分页＋有限批次。** 客户端逐页取曲目，分批提交；服务继续执行已受理任务。客户端关闭后，尚未提交的页不会自动下载。若要求提交一个集合 ID 后服务器自行持久展开，须单独批准新增导入任务，不能悄悄改变 T21/T23 的边界。
7. 本计划以 G01～G16 标记差距清单；这些编号只是索引，不替代既有 T/N 编号。确认后以子任务映射到既有任务，已完成父任务的历史证据不改写为“新功能已完成”。
8. 不因对照发现更多平台而调整既有平台路线顺序；新优先级须明确确认，并在 [platform-roadmap.md](platform-roadmap.md) 统一维护。

## 4. 逐项实现范围与验收

### G01 歌曲元数据与标签字段

- 映射：T21／T30 新子任务；前置：已有歌曲详情与标签处理器。
- 范围：扩展歌曲详情及内部标签输入，包含封面引用、曲目序号和专辑总曲数；平台有可信字段时映射，缺失保留未知。为 MP3／FLAC／M4A 写入曲目序号和总数，保留已有标题、多歌手、专辑与未知标签；不根据歌单位置伪造专辑曲号。
- 验收：三种容器的标题、多歌手、专辑、序号／总数逐项写入并重新打开读回；缺序号不生成 `0/0`；同一首在不同歌单位置不改变专辑曲号；重复处理不重复增加标签；音频载荷保持一致；旧 API 客户端与已有 fixture 仍可使用。

### G02 封面与歌词接入真实下载链路

- 映射：T21／T30 新子任务；前置：G01、相应平台的详情／歌词能力。
- 范围：在任务绝对期限与公共上游入场预算内，取得平台封面及歌词并交给标签处理器。网易云、5sing 先接已有歌词；酷我歌词由 G15 后补。封面支持经验证的 JPEG／PNG，先使用平台提供的适当尺寸；首轮不实现本地图片缩放或转码。
- 建议默认：基础标签、封面、歌词均开启，`metadata_policy=best_effort`；封面与歌词可各自关闭。封面下载上限建议 8 MiB，单次预算建议 10 秒且不得超过任务剩余期限；具体配置值随接口设计固化。
- 语义提案：分别记录字段的写入成功、上游确认不存在、能力不支持、获取失败、写入失败。`skip` 不发起仅为标签服务的封面／歌词请求；`best_effort` 允许可选项失败并报告；`required` 要求已启用、上游可提供的项写入成功，获取失败不能伪装成“不存在”。已确认纯音乐无歌词或平台明确无封面不会凭空变成下载失败。若用户需要“无封面也必须失败”，另增加显式必需字段选项，不隐式改变当前 required 含义。
- 验收：通过服务 API 下载有封面和歌词的真实网易云歌曲，读回封面字节／类型与歌词内容；含翻译时采用明确、确定的写入规则。覆盖纯音乐、封面 404、错误图片正文、超限、超时、取消、required 失败不发布与 best_effort 警告。配置改变后不误复用缺封面的旧文件；重启不改变已受理任务的元数据策略。

### G03 命名与目录分类

- 映射：T14／T30／T31 子任务；前置：G01。
- 范围：支持“歌名”“歌手 - 歌名”“歌名 - 歌手”三种命名；目标目录内支持平铺、按歌手、按歌手／专辑分类。默认保留现有“歌手 - 歌名＋平铺”。多歌手使用与现有显示一致的稳定拼接；缺失字段使用明确回退，最终仍可退回 source-id。
- 不包含：任意脚本模板、移动既有文件、全库重命名、按歌单重复复制同一文件。
- 验收：中文、多个歌手、空专辑、同名歌曲、Windows 保留名、长路径和非法字符都产生稳定可用路径；路径始终在获授权目标根下，含 `../` 的元数据不能越界；碰撞不覆盖；配置进入下载指纹，修改配置后旧任务路径不变；在子目录发布时注入退出，重启可恢复文件与记录。

### G04 网易云歌单与专辑

- 映射：N07／T23 新子任务；前置：已有公共集合端口。
- 范围：`search_playlists`、`playlist_detail`、`playlist_tracks`、`search_albums`、`album_detail`、`album_tracks`；映射封面、作者／歌手、描述、声明曲目数和顺序。歌单需要 trackIds 补详情时按当前页有界批量读取，不为请求一页而下载所有曲目详情。
- 验收：每个能力都有成功、空、无效 ID、权限、限流和字段缺失 fixture；稳定测试集合跨页不重复／不遗漏且顺序一致；人工构造超过 500 首的歌单，验证分批详情和最后一页；声明总数与实际可见数量分开报告，删除／不可见歌曲不能伪装全量成功；上游单次返回完整 ID 列表时也有正文与处理上限；至少一个真实歌单和一个真实专辑走服务 API 验证。
- 活跃集合边界：上游集合在翻页期间发生增删时，不承诺不存在的原子快照。检测得到版本变化时使游标失效或明确要求重新读取；上游不给版本时说明实时分页语义，不将分页结果宣称为固定时刻的完整快照。

### G05 三平台集合链接

- 映射：N07／T12／T22／T23 子任务；前置：对应平台集合能力；网易云依赖 G04。
- 范围：网易云歌单／专辑链接，酷我歌单／专辑链接，5sing 歌单链接。返回准确实体种类与稳定引用，再调用公共详情／列表能力；保留单曲链接行为。
- 不包含：未核实的短链、任意网站重定向。网易云 `163cn.tv` 当前不支持，作为后续独立协议探测，不为补齐本表自动开启。
- 验收：按各平台实际形式覆盖查询参数、fragment 和路径式链接；相同数字在 song／playlist／album 中不能混淆；伪造域名、非法 ID 和未支持类型明确拒绝；三平台各有真实集合链接读回与后续分页验证。

### G06 集合到有限下载批次

- 映射：T14／T23／T28 集成子任务；前置：G04、G05。
- 范围：用独立验收客户端演示“解析集合 → 逐页读取 → 用户选择或全部分批提交 → 查询批次／任务”。复用现有 API，不引入生产前端，也不新增后台无限展开。一个集合可以对应多个批次，保留原列表顺序和重复引用语义；进度明确区分“已提交页”和“已完成任务”。
- 验收：静态 230 项 fixture 按每批 100 项提交为 100／100／30，边界 100／101 项按现有契约处理；重复提交同 key 不增任务、同 key 不同请求冲突；一项参数非法时该批不创建其他任务；已受理后单曲权限失败不回滚其他已完成歌曲；重复项、取消与复用遵循既有批次契约。停止客户端后已提交任务继续，未提交页不声称已受理；服务重启恢复已受理任务。真实歌单和专辑各完成至少一批，并通过文件接口取回。

### G07 网易云真实账号与高音质

- 映射：N07 子任务；前置：已有 Cookie、品质规则、MP3／FLAC 验证。
- G07.a：有效／过期 Cookie 在线校验；普通账号、会员、单独购买与无权限响应分类；账号身份、默认账号切换和秘密头传递验证。
- G07.b：接入 `high`（按已验证的网易云档位映射）、`lossless`；先验证现有 WeAPI，确有必要时原生加入 EAPI 及固定加密向量，不为模仿参考代码实现无用途的 Linux API。
- G07.c：Hi-Res 独立样本与档位映射，独立声明；没有相应账号／曲目证据时保持未验收，不阻塞 high／lossless 子项交付。
- 验收：离线覆盖匿名、有效普通账号、有效会员、过期账号、购买限制、无版权、试听、限流、风控、地址过期；在线记录账号权限类别而不记录秘密。high 与 lossless 各完成真实解析、下载、文件读回，记录实际容器、码率／采样率等可测事实；Hi-Res 另有足以证明档位的协议与文件证据。strict 不静默降级，allow_lower 报告实际档位和降级警告；试听不得当整曲；不同账号不可复用私有缓存／音源；刷新地址后续传不拼接不同品质文件。
- 阻塞条件：无有效账号或目标档位样本时，仅可完成离线实现与普通路径测试，真实授权／品质验收保持待验收。账号通过已有秘密输入通道提供，不写入计划、命令输出或 fixture。

### G08 网易云发现能力

- 映射：N07／T23；前置：G04。
- 范围：分类与分类歌单、推荐歌单、榜单目录／详情／曲目；热门单曲可从已验证热歌榜派生，但明确来源，不假装为独立上游搜索。首轮采用可验证的公共推荐；个性化推荐不混入匿名结果。
- 验收：每个能力成功／空／不存在／限流；分类和榜单 ID 不跨源；曲目页大小不冒充榜单总数；派生热门项数量有界；缓存按能力、查询和身份分区。至少一个真实分类、推荐响应及榜单跨页请求通过公共 API 验证。

### G09 网易云扫码登录

- 映射：N07＋授权公共端口扩展；只复用 T24 所需部分，不以完成全部 OAuth 为前置。
- 范围：创建扫码会话、提供二维码载荷／登录 URL、查询等待／已扫码／成功／过期／失败状态、取消；成功后写入当前 principal 的 Cookie 凭据并返回凭据 ID。二维码绘制由客户端负责。保留手动 Cookie 入口，不增加密码登录。
- 验收：完整状态转换、期限、取消与成功竞争、重复成功回调只创建一个结果；会话、轮询、凭据均按 owner 隔离；登录 Cookie 不返回普通状态 DTO、不进日志；轮询受配额限制，服务重启后未完成会话明确失效，已提交凭据仍存在。真实手机扫码后完成凭据校验及一次有权限的歌曲解析；只有模拟轮询不能标记完成。

### G10 网易云个人歌单

- 映射：N07＋T21 的新能力子任务；前置：G04、可验证 Cookie；G09 是便利入口而非技术前置。
- 范围：只读列出当前账号创建／收藏的歌单，分页并复用公共集合详情；自建和收藏类型明确。新能力键／账号参数按现有 Provider 机制扩展。不包含创建、收藏、删改或账号间同步。
- 验收：无账号明确拒绝；两账号数据、缓存、游标不互通；切换／撤销账号使旧上下文按现行契约失效；空列表、最后一页、私有歌单无权限、会话失效有样本。使用真实账号读回至少一个自建或收藏歌单并展开；两账号隔离可用脱敏 fixture 补足，但真实账号成功证据不可省略。

### G11 网易云歌手热门曲目

- 映射：N07／T23；前置：已有 artist_tracks 端口、G06。
