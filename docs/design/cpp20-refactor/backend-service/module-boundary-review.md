## 前后端分工

| 功能 | 后端 | 前端／客户端 |
| --- | --- | --- |
| 搜索、分类、榜单、集合 | 平台协议、权限、聚合、分页 | 输入、展示、选择与页面排序 |
| 音源与品质 | 解析、品质证据、凭证 | 选择品质、展示实际结果 |
| 匹配与换源 | 候选、版本比对、探测、执行明确策略 | 选择候选，替换播放器音源 |
| 下载到音乐库 | 排队、传输、重试、取消、处理、保存到后端 | 提交与控制任务 |
| 保存到此设备 | 授权提供文件／媒体响应 | 接收、路径选择、写盘与进度 |
| 下载进度 | 持久快照、SSE／HTTP | 展示，与客户端保存进度分开 |
| 媒体访问 | 受控直链、可选代理、Range、授权 | 使用地址播放或保存 |
| 实际播放 | 提供数据 | 解码、声音输出、暂停、切歌、音量、倍速、循环、位置 |
| 播放队列与历史 | 首版不跨端同步 | 本地保存 |
| 歌词 | 获取、解密、统一时间格式 | 高亮、滚动与样式 |
| 文件标签 | 下载文件的标签、封面嵌入、必要解密 | 展示 |
| 身份与凭证 | 权限、账号秘密、版本和验证 | 授权交互与状态显示 |

后端 completed 只表示后端文件已发布；客户端写盘成功由客户端确认。媒体请求断开不取消独立下载任务。

## 已确认边界

| 问题 | 当前规则 |
| --- | --- |
| 播放会话与音源状态重复 | 复用 asset_id／file_id，移除独立 PlaybackSession |
| 后台下载与客户端保存混用 | 两段传输、两套进度，各自确认完成 |
| 直链／代理选择不明确 | media-access 统一选择 auto／direct／proxy；直链默认关闭且受资源条件限制 |
| 文件获取依赖后期在线播放 | 文件读取与票据在 S1 提供，在线代理在 S4 |
| 解析与媒体授权入口重复 | resolve 解析，media-access 读取既有资源并内部签发票据 |
| 音频处理与传输命名含混 | audio_processing 处理文件，application/media 编排授权，media_server 传输字节 |
| 身份存在两份权威存储 | SQLite 保存身份和 token 哈希；引导文件只用于一次性交付 |
| 逻辑模块被机械拆类 | 按生命周期、替换点和验证边界拆实现，不强制一名一类／库／线程池 |

保留后端任务队列、SSE + HTTP、入口线程隔离、Provider 与用例分离、文件与任务分离。它们分别解决常驻任务、状态恢复、资源隔离和生命周期差异；规则见[模块](feature-modules.md)与[运行时](runtime-and-tasks.md)。

## 本轮模块与功能拆分审查

审查范围：功能模块、编译依赖、内部契约、数据模型、API、运行时及多平台扩展。R1～R4 已于 2026-10-19 写入规范，状态为“设计已补齐、实现待验证”。当前只有工程骨架，本轮不开发业务代码，也不把静态文档检查当作功能验收。

总体判断：保留一个进程内的分层模块、小能力 Provider、统一任务执行与发布、独立文件资产和三个入口的资源隔离。本轮补全契约与责任归属，延续按生命周期、替换点和验证边界拆分实现的原则。

### R1 · P1：下载意图与去重——设计已补齐

原问题：指纹遗漏试听／标签策略与手动目标，可能错误复用不同要求的结果。

已确定：application/tasks 生成 NormalizedDownloadIntent，domain 定义规范字段与指纹规则，Repository 原子去重。指纹包含试听、元数据、稳定手动目标、固定账号绑定及有效产物策略；临时 match/context 句柄和 token 版本不作为下载身份。完成结果还要通过权限、文件与策略复核。

规范：[下载意图](data-models.md#幂等与下载去重)、[任务端口](internal-contracts.md#4-任务端口与状态写入)、[API 创建／重试](api-contract.md#9-下载任务)。幂等重放先于临时上下文检查，任务 retry 使用持久目标；验收 A35～A37、A46。

### R2 · P2：账号身份隔离——设计已补齐

原问题：同 principal 下两个账号可能具有相同版本，仅凭版本无法隔离缓存和分页。

已确定：CredentialService 唯一生成 AccountBinding 与 AuthIdentityKey，分别表达稳定选择与带版本快照；anonymous／application／user 明确区分，用户 OAuth 保留所依赖应用身份。缓存、上下文、游标、在途合并和连接租约共用完整键。任务绑定在接收时固定，刷新只更新授权版本。

规范：[账号模型](data-models.md#账号绑定与授权身份)、[缓存与失效](runtime-and-tasks.md#搜索与缓存)、[API 分页](api-contract.md#4-幂等分页和超时)。授权变更后的旧游标返回 410，旧工作不能污染新身份分区；验收 A38～A40。

### R3 · P2：授权协议扩展——设计已补齐

原问题：刷新已有需求，但平台协议工厂与公共协调层之间缺少明确注册契约。

已确定：平台包通过 auth_profiles 注册 ICredentialVerifier、ICredentialRefresher、IApplicationTokenProvider，以 source + auth_profile + kind 唯一绑定。application/accounts 负责账号选择、刷新合并和条件提交；平台 auth 目录负责协议，基础设施负责通用服务认证、网络、秘密和存储。

规范：[授权工厂与调用](provider-extensibility.md#授权能力注册与调用)、[秘密提交](internal-contracts.md#62-凭证和秘密提交)、[目录边界](modules-and-layout.md#公共边界)。声明由绑定生成，启动验证缺失／重复工厂；刷新不递归占用同池、不覆盖人工更新；验收 A40～A41。S1 不强制实现 OAuth。

### R4 · P2：任务调度与上游入场——设计已补齐

原问题：任务执行槽与上游额度职责交叉，跨来源和重定向时计量、等待与释放不明确。

已确定：downloads/Scheduler 管理持久领取、公平性和执行槽；runtime/admission 是唯一额度账本，通过 UpstreamAdmissionPort 对实际 source、origin、流量类别和稳定应用组联合发放租约。Transport 校验并消耗租约，真实结束才归还，重定向／刷新独立入场。

规范：[入场与租约](runtime-and-tasks.md#上游入场与租约)、[任务延后](runtime-and-tasks.md#入队与调度)、[端口](internal-contracts.md#34-上游入场端口)。Deferred 不占 worker 等待；下载使用 waiting_retry + wait_reason=admission 持久延后，不额外消耗逻辑 attempt，重新领取更换 execution_id，deadline 不延长；验收 A42～A45。

### 确定的模块边界

| 模块 | 应拥有的职责 | 拆分粒度 |
| --- | --- | --- |
| domain | 值对象、纯策略、状态迁移、下载意图与指纹规则 | 不依赖框架，不承担 I/O |
| application | 搜索／集合／资源／任务命令查询／账号／媒体授权／事件用例及端口 | 按业务目录组织，不强制每个 Service 单独成库 |
| providers | 平台协议、能力组合、平台授权协议与私有上下文 | 每个平台独立适配包，已有公共能力不按平台修改 |
| downloads | 持久任务调度、Runner、重试／续传、Finalizer、Recovery | 与请求线程分离；发布协调不放入文件处理器 |
| audio_processing | 解密、格式验证、标签与处理报告 | 不改任务状态、不发布最终文件 |
| infrastructure | HTTP 客户端、数据库、文件、秘密和外部进程适配 | 先按目录隔离，出现实际依赖裁剪需求时再拆库 |
| runtime | 执行器、入场额度、取消及停机基础机制 | 不解释歌曲、下载状态或平台业务错误 |
| api／media_server／event_server | 各自协议和连接生命周期 | 保留独立监听／线程池；共用身份、CORS、错误等规则，无需复制业务服务 |
| src/server | 配置、组装、启动与退出 | 具体实现仅在此连接 |

最小安全发布与重启恢复已直接列入 [S1 完成条件](README.md#功能分期)，S3 扩展故障覆盖。多平台、OAuth 与复杂匹配按需交付；新增验收及实施阶段以[验收关口](flows-and-acceptance.md#8-验证层次与实施关口)为准。逻辑职责不强制对应一个类、库或线程池。

## 范围限制

- v1 下载明确提交的 TrackRef。未分页取得或未提交的歌曲不会在关闭前端后自动入队；完整后台歌单导入需独立持久用例，负责枚举、去重、进度和取消。
- 收藏、个人播放历史、同步队列、设备遥控不写入 DownloadTask 或媒体句柄；需要跨设备同步时另设用户资料／设备能力。
- 封面仅返回公开 URL；需要秘密头且无专用图片代理时返回 null／警告。
- 客户端直接传流保存不保证关闭客户端后继续；需要后台保证时创建后端任务。
- 批次可复用任务。取消真实任务会影响其他批次引用，不能解释成只移除某个列表项。
