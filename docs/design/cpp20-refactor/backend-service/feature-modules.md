# 后端服务功能模块详细设计

设计日期：2026-10-19。基线为 C++20、CMake、FetchContent 浅克隆、cpp-httplib；Drogon 保留替换适配层的可能。本文件定义功能模块的具体职责和协作方式，供后续实现使用；工程和实现代码尚未创建。

对外字段与状态码以 [API 契约](api-contract.md)为准，数值配额以[运行时](runtime-and-tasks.md)和[配置](configuration-and-deployment.md)为准，内部操作与所有权见[内部契约](internal-contracts.md)。这里不另建一套不同的默认值。

## 1. 服务边界和功能分组

交付一个可独立运行的 `music-dl-server`。它负责音乐平台通信、账号凭证、搜索与发现、音源选择、后台下载、文件资产和媒体传输；前端负责页面、播放队列、播放器解码与用户交互。前端退出不结束已提交下载。

三个 HTTP 入口位于同一进程，共享业务服务与数据库：控制入口承接短请求，媒体入口传输音频，事件入口保持 SSE 订阅。端口是部署参数，前端通过 info 获取访问地址。无需为每个平台启动一个服务，也不启动 Go 或 Node SDK 作为默认运行依赖。

| 功能组 | 主要模块 | 对外能力 | 主要状态归属 |
| --- | --- | --- | --- |
| 服务基础 | ProcessHost、配置、身份、运行时 | 健康、能力、限额、管理状态 | 配置快照、生命周期、配额 |
| 音乐目录 | Catalog、Collection、Discovery、Lyrics | 搜索、详情、分类、榜单、歌词 | 短期缓存和分页游标 |
| 平台访问 | ProviderRegistry、Provider、Transport | 供业务模块调用平台能力 | 能力描述、凭证版本、连接租约 |
| 音源选择 | Resolve、Probe、Match | 音源描述、品质、探测、换源 | 有期限的音源和匹配上下文 |
| 下载任务 | Command、Scheduler、Runner、Recovery | 创建、批量、取消、重试、进度查询 | SQLite 任务和尝试记录 |
| 音频与文件 | Processor、Finalizer、FileAccess | 解密、验证、标签、文件获取 | 临时文件、发布意图、不可变资产 |
| 播放 | Playback、MediaTicket、StreamBridge | 播放会话、Range、媒体授权 | 有期限的会话与有界流缓冲 |
| 进度通知 | TaskEvents、SseResponder | SSE 推送，与 HTTP 查询并存 | 按身份隔离的短期订阅队列 |

功能组不是微服务，也不要求每个组件都建一个静态库。编译目标按[目录设计](modules-and-layout.md)组织，组件以清晰的职责和依赖边界区分。

## 2. 服务启动与组装模块

`ProcessHost` 管理进程状态：initializing、recovering、ready、draining、stopped；必需初始化失败进入 failed 并退出。它管理组件寿命，不执行具体搜索或下载。

`CompositionRoot` 按依赖顺序组装配置、身份、数据库、文件系统、HTTP 传输、平台注册、应用服务、调度器和三类入口。工厂只在此处选择 httplib 等具体实现，业务模块通过端口调用能力。

启动先验证配置、目录和实例锁，再打开数据库和进行恢复，之后开放监听与 readiness，最后允许调度领取任务。可选平台临时不可达只影响该平台，数据库无法打开或已启用监听绑定失败则阻止 readiness。

关闭时先拒绝新任务和新订阅，再停止领取任务、关闭事件与媒体流、保存下载恢复点，最后等待可控工作退出并关闭数据库。生命周期回调不得反向访问已销毁的服务；取消信号和条件变量先唤醒，线程 join 后再销毁其状态。

可配置管理动作首版仅包括暂停领取新下载任务；暂停不取消已经运行的任务。平台配置、线程数、监听地址变更通过重启生效，避免第一版引入完整热重载。

## 3. API 接入与身份模块

### 3.1 控制入口

请求处理顺序为：解析与大小约束 → request_id → CORS／预检 → token 与 scope → DTO 校验 → 资源归属 → 入场额度 → 应用用例 → 响应映射。请求 body 不直接反序列化成可以执行的任务对象。

入口只负责 HTTP 与业务类型转换。Provider 不返回 HTTP 状态码，下载 Runner 不直接持有 Response，错误映射只在入口集中完成。响应发出后不能有后台回调再修改它。

### 3.2 身份与账号分离

`PrincipalService` 识别调用本服务的人；`CredentialService` 管理这个人访问某个平台的账号。平台 Cookie 不等于后端访问 token，不能用 Cookie 决定任务 owner。

凭证更新生成新版本。新请求使用新版本，在途请求持有旧版本的独立快照，不能修改共享 Client 的 Cookie 来切换账号。删除凭证后禁止新租用，正在执行的请求根据显式取消与时间预算退出；已经获得秘密副本的请求无法靠删数据库记录瞬间撤回。

凭证验证是显式受限的上游操作；失败记录原因和检查时间，不覆盖原秘密为错误页。默认凭证选择必须按 principal + source 唯一确定，不能随数据库返回顺序变化。秘密的写入与描述记录协调见[内部契约](internal-contracts.md)。

## 4. 平台注册与适配模块

### 4.1 一个平台注册项

| 组成 | 职责 |
| --- | --- |
| Descriptor | 稳定 source、显示名称、能力、分页方式、品质提示、凭证需求 |
| 协议构造器 | 参数、路径、签名、加密与必需请求头 |
| 能力实现 | 搜索、集合、发现、解析、歌词等单平台操作 |
| 响应解析器 | 平台字段与业务码转换为统一模型和 DomainError |
| 上下文处理器 | 提取并恢复后续解析所需的非秘密平台附加数据 |

ProviderRegistry 启动时显式注册选定平台并冻结。未启用、未实现能力、临时不可用分别表达；缺某一能力不影响该平台其他能力。

Provider 方法一次只完成约定的平台用例，不自己进行全平台搜索，不创建下载任务，不选择其他平台，不直接访问 SQLite。复杂操作可能发多个平台请求，但必须消费调用者同一个截止时间和连接额度。

### 4.2 协议和复用边界

平台 JSON 保留在具体适配器内。公共模型不增加任意私有参数字典；必要上下文以 owner 绑定的 context_ref 提供，任务入队前保存可重建所需的非秘密快照。

平台自己的 AES／RSA／摘要／签名属于协议层，HTTPS 属于传输层。签名算法、时间戳与随机值通过可替换依赖提供，以便离线固定输入验证。遇到字段变化返回解析错误，不输出看似成功的空列表。

研究的 Go 和 npm SDK 作为协议理解依据。迁移每个端点时登记研究提交、请求字段、响应样本、凭证条件和错误分类；具体平台接口仍需独立验证，不以“SDK 有这个函数”作为已支持的证据。

## 5. HTTP 上游传输模块

Transport 提供两类能力：有大小上限的 JSON／文本请求，以及逐块交给消费者的音频响应。两者共用 TLS、重定向、连接、取消和错误分类规则，但不共用无界正文缓冲。

ClientLease 独占一个正在使用的客户端；连接池键含 origin、身份、凭证版本、代理和 TLS 策略。租约结束前网络操作必须真实退出，不能因为业务等待超时就把仍在读取的 Client 放回池。

重定向每跳重新校验平台允许的目标范围和敏感头传播策略。客户端不能提交任意 URL 交给后端下载；分享链接先由平台路由器识别，解析后的 CDN URL 也遵守对应平台的地址规则。

短请求由受限上游执行器运行。下载 Runner 直接流式接收至自己的工作文件；媒体请求通过 StreamBridge 传至播放器。接收器返回停止或触发取消时，Transport 释放真实连接后才释放预算。

重试分层：Transport 处理允许的瞬时传输失败；TaskRunner 决定是否重新解析和再尝试；框架入口不自动重放创建任务。不能让每一层分别无限重试同一错误。

## 6. 搜索模块

`SearchService` 统一编排歌曲、歌单、专辑、歌手四类搜索。`SearchPlan` 保存来源集合、关键词、各源分页、凭证快照和绝对截止时间；各来源结果相互独立。

处理步骤：

1. 校验来源与搜索类型；未知 source 整体报错，已知但能力缺失记录逐源结果。
2. 将关键词做受限空白处理，保留原始文本；不擅自删除可能代表录音版本的词。
3. 检查按身份隔离的缓存，验证续页游标绑定信息。
4. 通过公平调度限制在途来源数和各平台并发；不要阻塞工作线程等待平台 semaphore。
5. 调用对应 Provider，统一字段、保留 source/id，生成每个来源自己的下一页游标。
6. 在截止时间内聚合已完成结果，返回成功、空结果或逐源错误。

首版不把不同平台的同名歌曲合并为一个 ID，也不按不可比较的平台分数进行全局排名。顺序按平台注册顺序分组，组内保留上游顺序。页面需要“同一歌曲的其他来源”时调用 MatchService。

缓存不保存失败为空结果，缓存失效不能改变任务身份。一次搜索超时后，迟到结果不写入该 HTTP 响应；是否写缓存由未取消、凭证版本仍有效等条件决定，首版可直接丢弃迟到结果。

## 7. 集合与发现模块

### 7.1 歌单、专辑和歌手

`CollectionService` 分离详情和条目分页：详情查询不隐含拉取全歌单；拉第一页不声称得到完整专辑。保持上游曲目顺序，缺失或不可访问曲目不能用邻近曲目替代。

集合可能在分页期间变化。首版游标保存平台 continuation 与可用版本证据，不声称跨多页得到平台事务快照；识别到版本失效时要求从第一页重新读取。客户端选定下载项后，任务持有 TrackRef 快照，之后歌单变化不自动增删这些任务。

“下载整个歌单”第一版由客户端分页获取并显式提交所选 TrackRef，按批次上限分组。每批创建原子，但多个批次之间不原子；若中途失败，客户端保留各批幂等 key 继续提交。先不增加隐含后台抓取无限歌单的任务类型。

### 7.2 分类、排行榜和推荐

`DiscoveryService` 返回分类目录、分类歌单、排行榜目录、榜单详情与曲目、推荐歌单。分类 id 与榜单 id 只在其 source 内有效。

目录来源显式标为实时平台数据、内置配置或搜索派生。内置分类的版本由 Provider 维护，不伪装成动态平台目录；平台缺失分类接口时声明不支持，不能默认套用另一个平台的标签。

榜单排序以平台为准。更新时间未知返回 null，不能用后端请求时间代替榜单更新时间。推荐结果根据账号可能不同，缓存必须隔离身份和凭证版本。

### 7.3 歌词、分享链接和封面

LyricsService 统一普通 LRC、翻译与逐字歌词的时间单位。未知格式保留结构化错误或警告；不能要求每个前端实现平台解密。没有歌词与平台根本不支持歌词分开表达。

LinkParseService 从分享文本识别允许的平台链接，有限展开短链后返回实体类型和 ref，不直接启动下载。重复识别结果按实体身份去重；v1 单实体契约遇到多个不同目标时返回参数错误并让调用者缩小输入。

封面优先返回公开可访问地址；需要额外秘密头但尚无对应授权封面资产能力时返回 null 或警告。完整封面缓存／图片代理不是现有音频文件路由的隐含能力，后续增加时需独立契约。

## 8. 音源解析与探测模块

ResolveService 输入原曲引用、品质策略和身份，输出公开 AssetDescriptor 与内部 ResolvedAsset。解析器得到的 URL、Cookie、密钥只保留在后端；前端得到描述和后端播放／文件入口。

品质选择顺序为：确定实际曲目 → 获取该账号可用资源 → 比较请求品质与证据 → 检查试听策略 → 返回描述。strict 不静默降级，allow_lower 才选择允许的较低档位；文件扩展名不能独立证明无损或高解析度。

ProbeService 检查资源可访问性、大小、格式和资源一致性证据。优先使用合适的 HEAD；平台不支持时采用受字节和时间限制的 GET 探测。上游忽略 Range 时必须提前停止，不为“探测”下载整首歌。

探测结果不是长期可用承诺。下载开始或播放器发起新 Range 时仍须验证响应头、状态和身份；解析缓存过期后重新解析，不能让已排队任务依赖失效 asset_id。

## 9. 换源与匹配模块

MatchService 用后端取得的原曲元数据搜索其他来源，再筛选候选。它不接受客户端随意声明“这两首相同”作为证据。

| 阶段 | 规则 |
| --- | --- |
| 查询构造 | 标题与主要艺术家为主，必要时增加专辑信息；保留版本标签 |
| 标准化 | 大小写、空白、有限标点归一，原始值仍保留 |
| 硬性排除 | 已知 live／studio、cover／原唱、instrumental／有唱等明确冲突 |
| 候选排序 | 标题、艺术家、时长、专辑与版本证据综合评分；未知字段不当作完全相同 |
| 有限探测 | 仅对有限候选解析和检查资源，不对全部搜索结果下载 |
| 输出 | match_id、candidate_id、实际歌曲、分数、理由、可用性和到期时间 |

评分权重与自动通过阈值须用标注样本验证，未验证前仅提供手动候选；不能把某个经验分数解释为正确概率。自动换源默认关闭，启用需同时满足服务开关、请求策略和已验证的最低匹配条件。

自动候选计划有固定候选集合和已尝试集合，不能 A 失败切 B、B 失败又切回 A。权限失败、明确不可用、网络失败等是否可触发换源由错误策略白名单决定；未列明类别停止并报告，不借自动换源隐藏所有错误。

换到另一曲目后必须重新建立资源与临时文件，不能继续向旧 partial 追加字节。在线播放开始后固定实际录音，仅允许刷新同一资源的地址；要换另一录音就创建新播放会话。

## 10. 下载命令与查询模块

DownloadCommandService 管理创建、批量创建、取消和手动重试；TaskQueryService 读取已提交公开快照。这两个服务不执行整首音频传输。

创建先校验权限、目标、上下文和策略，再在短事务内处理幂等、去重、配额、批次关联和任务记录。事务成功才返回任务 ID；调度唤醒失败由扫描兜底。相同幂等输入重放不产生新任务。

取消接受与执行退出分开：活动任务先进入 canceling，再由 Runner 清理至 canceled；进入 finalizing 后拒绝取消，避免文件已经发布却宣称取消成功。手动重试创建新任务并记录 retry_of，不修改旧任务历史。

HTTP 列表和单任务查询始终独立可用，返回持久公开进度而非任意 worker 的临时计数；不要求 SSE 连接存在。单任务支持弱 ETag，列表按稳定游标分页。查询进度不发起平台请求。

一个任务可以属于多个批次，关系由 batch_items 表表示。批次只是有序任务集合，取消批次会取消其引用的真实任务；另一批次复用同一任务也会看到取消结果。

## 11. 调度与执行模块

### 11.1 调度器

Scheduler 只领取符合时间、身份、平台配额的任务，按 principal 轮转，避免一个账号塞满队列。任务权威队列在 SQLite，内存只保存可重建索引与唤醒信号。

领取同时生成 execution_id，记录尝试和执行租约；Runner 每次写状态必须带该执行标识与预期版本。取消后到达的旧回调、上次尝试的进度或恢复前的 worker 都不能覆盖当前状态。

waiting_retry 只记录下次运行时间，不占工作线程睡眠。processing 阶段占处理额度，不占上游音频连接；首版 Runner 可等待有界处理结果而继续占一个下载执行槽，吞吐量按这个保守模型计算。

### 11.2 Runner

执行链为解析 → 探测 → 接收 → 文件处理 → 发布。Runner 持有独占任务工作区、取消源与执行标识，真实网络和文件操作由端口执行。切换阶段前检查取消和剩余预算，不在共享锁内调用第三方代码。

ProgressAccumulator 汇总本次尝试字节、总大小、滑动窗口速度和 ETA；总大小或速度未知返回 null。续传进度包含已验证的已有字节，重下时显式重置本次文件进度，因此进度不保证跨尝试单调增加。

公开进度提交后递增 version 并通知 SSE。网络接收完成只进入 processing；完成状态必须等文件发布与资产记录协调成功。磁盘写失败立即结束传输，不继续“下载到内存里等磁盘恢复”。

### 11.3 重试与恢复

RetryPolicy 分类可恢复网络、资源过期、账号权限、解析协议和本地文件错误，决定是否重试、重新解析、等待或终止。总尝试数、每次传输重试和总截止时间统一约束，不能相互重置。

ResumePolicy 先验证保存的资源身份和 partial 长度，再决定请求 Range；200、206、416 按[运行时](runtime-and-tasks.md)处理。仅文件名一致或歌曲时长相近不构成追加字节的条件。

Recovery 启动时先处理发布意图，再恢复活动任务。没有可信检查点就重新下载；无法访问目标目录则报告文件错误，不把工作文件转存到另一个意外目录。

## 12. 音频处理和文件模块

MediaProcessor 管理格式检测、必要解密、结构验证、可选标签与歌词写入。每个步骤报告 changed、warnings、fatal_error 和产物，不直接修改任务为 completed。

默认保留平台原始编码；转码不是基础下载和代理播放的必经步骤。格式不受当前标签库支持时，best_effort 可保留音频并给警告，required 则失败。必要解密或结构验证失败不能作为 best_effort 标签失败忽略。

FileWorkspace 将临时产物放在目标目录同一文件系统的任务工作区；AssetStore 负责路径预留和不可变文件读取；Finalizer 负责发布意图、同文件系统重命名、资产记录与任务终态协调。

音频是主资产。可选歌词等侧文件单独记录处理结果，首版 best_effort 侧文件失败不撤回已验证音频；若声明必需产物则必须纳入发布意图与恢复集合。不得默认认为多个文件的重命名具有原子性。

输出路径由后端配置和可信元信息生成；客户端选择 destination_id，不能传绝对路径。已完成文件被外部移动后标记 missing，查询任务历史仍保留，媒体读取返回明确文件缺失。

## 13. 播放和媒体模块

PlaybackService 创建会话时解析并固定实际录音，保存有期限的内部资源描述。客户端播放器负责解码、音量、播放列表和暂停；暂停通常表现为停止／暂停读取，不应建立一个持久下载任务。

本地已有文件通过 FileAccessService 返回授权媒体入口。在线资源通过 StreamBridge 边读边转发，缓冲有上限；前端拖动进度条产生新的 Range 请求，按当前资源身份处理。后端不需要先把完整音频下载到磁盘才能开始转发。

向下游发送响应头前验证上游状态和 Range。传输中途失败只能关闭字节流并记录错误；不能把 JSON 错误拼入音频内容。客户端断开只取消该次媒体传输，持久下载任务不受影响。

MediaTicketService 为不能带 Bearer 头的播放器提供短期、目标受限的 URL。票据与 SSE 授权分开；SSE 首版通过带 Authorization 的 fetch 流或原生 HTTP 客户端接入。

播放与下载首版不共享同一在途字节流或未发布 partial。它们可以复用授权元数据查询，但各自有资源预算与取消语义；只有完成发布的不可变文件可被直接复用播放。

## 14. SSE 与进度模块

TaskEventService 接收已提交的任务公开投影，按 owner 找到订阅；SseResponder 将投影编码为 SSE。每个前端一条连接覆盖全部有权任务，HTTP 查询始终保留。

事件仅用于通知，数据库快照才是事实。首版不实现事件日志重放；首次连接与重连都先注册订阅，再查询当前状态，最后按版本合并连接期间收到的更新。

订阅队列有字节和条数双重上限。同一任务尚未发送的普通进度可合并，但不能在活跃连接中悄悄漏掉终态；超限关闭该订阅，要求重连重新同步。下载线程不等待客户端网络发送。

发布事件顺序由提交后的分发序列控制；即使并发回调迟到，也只接受 task.version 更新的投影。无法完成可靠分发时关闭受影响连接，客户端从 HTTP 恢复，不能为了 SSE 故障回滚完成任务。

SSE 入口有独立线程池和配额、心跳、写超时、连接寿命。单纯把发送逻辑放到后台线程不等于 httplib 非阻塞；隔离长连接的目的就是保留搜索和取消接口的服务能力。

## 15. 存储、缓存与观测模块

Repository 以 owner 条件读取和修改实体，不能仅依赖 API 层提前检查一次权限。持久变更通过单写入执行器提交，读连接只承载有时限、有限行数的查询。

缓存按 principal、source、凭证版本和操作参数隔离。缓存项、游标、音源描述、播放会话分别有寿命，不能将其中一个过期错误误判为下载历史不存在。进程重启只使短期句柄失效，持久任务和文件索引仍存在。

Observability 记录模块、操作、source、request_id、task_id、耗时和去敏错误。指标分开统计控制等待、平台请求、下载传输、处理、数据库、媒体流和 SSE 占用；不记录 Cookie、密钥和可复用票据。

数据库暂不可写时，不发布尚未提交的新版本进度或 completed。Runner 尝试在预算内暂停推进并保留恢复材料；无法提交状态时报告服务不健康，由恢复流程处理，不用内存 completed 冒充成功。

## 16. 功能完成与实施顺序

| 阶段 | 模块交付 | 可观察完成条件 |
| --- | --- | --- |
| S0 | ProcessHost、身份、配置、Repository、Transport 边界 | 启停可靠，配置失败明确，线程与数据寿命受控 |
| S1 | 单平台 Search／Resolve、下载命令与 Runner、HTTP 查询、SSE、文件读取 | 关闭前端下载继续；重连看到完整状态；能取回正确文件 |
| S2 | 更多 Provider、歌单／专辑／歌手、分类／榜单／歌词／链接 | 能力差异、各源分页、账号隔离、部分失败可解释 |
| S3 | Retry、Resume、Recovery、Processor、Finalizer 完整验证 | 断网、重启、磁盘故障和发布中断不产生伪完成或混合文件 |
| S4 | Playback、Range、媒体票据、Match 与受控自动换源 | 拖动播放、慢消费者、同曲资源刷新和版本匹配行为明确 |
| S5 | 平台部署与长期运行验证 | Windows／目标 Linux 和 NAS 架构实际构建、启停、持久数据验证 |

S1 需具备最小可靠发布和安全重启处理，S3 扩展续传、复杂处理与故障覆盖；不能把防止伪完成推迟到后期。TLS 后端、标签库、首批平台与自动匹配阈值仍需专项验证，主模块边界不依赖这些细节提前锁定。
