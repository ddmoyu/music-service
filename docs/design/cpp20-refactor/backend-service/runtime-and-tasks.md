# cpp-httplib 运行时与后台任务

本文件定义阻塞 I/O 主方案的执行与资源边界。所有数字是可配置的初始值，需要在目标设备验证，不是已达成的性能保证。

## 一个进程，三套 HTTP 监听

控制 API 使用独立的 `httplib::Server`，默认监听 17632；文件和音频代理监听 17633；SSE 事件监听 17634。三个实例共享服务、授权、SQLite 和配置，分别使用独立 TaskQueue。未启用的媒体／事件功能不启动相应监听。

长响应的 ContentProvider 仍会占用服务工作线程；仅把上游请求放进另一个线程池，不能释放负责向客户端发送音频的服务器线程。因此这里在监听和线程池层面隔离媒体流，不能把 content provider 当成非阻塞 HTTP。[httplib 固定版本说明][httplib-readme]、[接口与线程池源码][httplib-source]

客户端从 `/api/v1/info` 获得 media_base_url 和 events_base_url，或使用返回的完整链接。反向代理可将三套路径映射到同一外部 origin；直接部署使用三个端口，不要求前端推算端口关系。

## 执行器和额度

| 资源 | 初始值 | 调度与排队 |
| --- | --- | --- |
| 控制 HTTP 工作线程 | 16 | 有界连接待处理队列 64 |
| SSE HTTP 工作线程 | 8 | 连接队列 16；活动订阅全局最多 6、每 principal 最多 2，预留处理拒绝／预检的余量 |
| 昂贵控制操作 | 全局 8、每 principal 2 | 搜索、匹配、解析等先非阻塞获取额度；额度不足即响应 |
| 短上游请求池 | 8 个线程 | 待执行 64；每平台短请求最多 2 个在途 |
| 单次聚合 fan-out | 最多 4 个平台在途 | 后续来源按公平调度推进，整个请求有截止时间 |
| 下载执行池 | 3 个线程 | 每平台下载最多 2 个；排队存 SQLite |
| processing 池 | 2 个线程 | 最多排队 16；重写标签、全文件解密等工作 |
| 媒体 HTTP 工作线程 | 8 | 连接待处理队列 16 |
| 媒体响应 | 全局 6、每 principal 2 | 其中上游播放流最多 4、本地文件发送最多 4，总数仍不超过 6 |
| 媒体上游池 | 4 个线程 | 已拿到播放额度才启动，不排长队 |
| 全部上游连接 | 合计最多 16 | 短请求、下载、播放均占用；重定向也计入相同预算 |
| SQLite 写执行器 | 1 个线程 | 排队 128；短事务，繁忙超时后返回明确错误 |
| SQLite 读取连接 | 最多 2 | 查询有超时与条数限制 |

搜索与媒体隔离不保证任意负载下完全无延迟。慢连接、CPU、磁盘和数据库仍可能影响全进程；通过读写超时、容量和公平调度把影响控制在明确范围内。

请求已到业务入场层：单调用方额度不足返回 429，整体容量不足返回 503，并附 Retry-After。若连接在 httplib TaskQueue 入队之前就被拒绝，可能只能关闭连接，不能承诺一定发出 JSON 429／503；客户端应将连接失败与业务限流分别处理。

### 不允许的等待关系

控制 HTTP 线程可以等待有界短请求池，但短请求池不能反向等待控制线程。下载线程可以提交 processing 或数据库操作；processing 和数据库执行器不能反向等待下载线程。任何线程不在持有共享调度锁或数据库事务时等待网络、文件处理或另一个 future。

平台额度由调度器在派发前获取，不能让所有短请求工作线程都阻塞在同一平台的 semaphore 上；这样其他平台才有执行机会。任务结束或取消时按 RAII 释放实际持有的额度；仅仅向客户端返回超时不表示底层请求已结束，不能提前把额度当成空闲。

## httplib 适配规则

| 位置 | 设计 |
| --- | --- |
| 服务 TaskQueue | 显式设置基础／最大线程与队列容量，不依赖库版本默认值 |
| Client 所有权 | 一次请求独占一个 ClientLease；连接复用仅在 origin、凭证版本、代理、TLS 策略一致时进行 |
| 普通响应 | JSON／文本默认最大 2 MiB，读取超过上限中断；错误响应也限制体积 |
| 下载响应 | response handler 校验状态与头，content receiver 按块写任务独占文件，不累积完整 body |
| 传输取消 | stop_token → 当前传输句柄；在接收回调中检查，并使用适配器验证过的 stop／关闭方式 |
| TLS | 校验证书链与主机名；按实际编译后端配置可信根，不借关闭验证解决上线问题 |
| Cookie | 显式上下文传入；禁止全局“当前平台账号” |
| 重定向 | 每跳重新校验地址和协议，最多 5 跳，清除不应跨来源发送的敏感头 |
| 错误 | 保留网络类别、HTTP 状态、平台业务码；不把 403 一概说成断网 |

`ThreadPool` 构造参数及 `Get` 的 response handler／content receiver、`stop()` 等均在已检查源码中存在；这些是适配依据，不能据此跳过取消、TLS、重定向组合的集成验证。[固定版本源码][httplib-source]

### 截止时间与请求生命周期

搜索默认总预算 10 秒，客户端可以在 1～15 秒范围指定更小／更大预算；每来源默认 5 秒，且不晚于总截止时间。排队时间也计入预算。底层连接、读与写超时分别设置，不能拿某个 socket 空闲超时冒充端到端总截止时间。

等待过程中监测前端断开和取消；超时后聚合返回已完成结果，并请求取消剩余工作。任务只持 shared operation state 的值拷贝，不捕获稍后已失效的 Request／Response 引用。迟到结果不得再写响应，也不得覆盖新搜索。

DNS、TLS 或系统调用能否即时中断需要按适配器验证。在尚未能即时中断的路径上，保留任务句柄与额度直到其真实退出；设置连接和空闲上限，避免把未结束工作隐藏成“已取消且不占资源”。

## 搜索与缓存

缓存键至少包含 principal、来源、凭证版本、操作、查询与页游标，防止不同账号结果互相污染。初始歌曲／集合响应缓存 TTL 60 秒，全体最多 128 项、总估算大小上限 16 MiB；受权限数据只在对应 principal 内共享。

平台禁用、凭证更新、相关配置变化使对应缓存失效。失败不缓存为成功空列表；可对短时重复失败做最多 5 秒的错误抑制，并保留错误类别。SourceResult.cache 必须说明是否命中与数据时间。

匹配请求可以共用同一 principal 下的在途查询，但每位等待者有自己的截止时间；最后一位等待者退出后才取消可共享的操作。首版不为这种优化引入跨用户共享结果。

## 下载状态机

```text
queued → resolving → probing → downloading → processing → finalizing → completed
   │         │          │            │             │
   │         └──────────┴────────────┴─────────────┴→ failed
   │                              │
   │                       waiting_retry → resolving
   │
   └→ canceled

resolving / probing / downloading / processing → canceling → canceled
waiting_retry → canceled
```

只有被分类为可重试的失败进入 waiting_retry；图中的失败出口不表示所有失败都直接进入同一重试规则。`probing` 可在已有足够证据时跳过；processing 至少完成必需格式与长度验证，可跳过可选标签。

`completed`、`failed`、`canceled` 为终态。手动重试 failed／canceled 任务创建新的 task_id、设置 retry_of，不把旧终态任务原地改成 queued；新的客户端可保留旧失败记录。自动网络重试仍属于原任务，不需要客户端调用 retry。

### 入队与调度

先完成身份、参数、目标目录与容量校验，再在一个数据库事务中处理 Idempotency-Key、下载指纹、任务与批次。提交成功才能返回 202；提交失败返回 503，不能先告诉前端已创建再依赖稍后落盘。

调度器按 principal 轮转，再按各 principal 内的 created_at 和可用平台额度选择任务。默认每 principal 最多 500 个未终态任务，实例最多 2000 个；100 项批次也纳入同一额度。被平台限制的队首任务不应阻止其他来源运行。

领取任务通过条件更新和执行租约完成，同一任务同时只能有一个 runner。内存唤醒失败时由周期性 DB 扫描兜底；一个 data_dir 同时只允许一个进程，因此首版不承担跨节点租约协调。

### 执行阶段

1. 读取任务快照与当前可用凭证版本，记录此次执行所用版本。
2. 根据原始 ref 获取必要上下文，执行品质及明确启用的换源策略。
3. 检查资源是否试听、品质是否满足、大小与空间是否允许；获得一致性证据。
4. 分配目标目录内 `.music-dl-work/{task_id}/`，打开唯一临时文件。
5. 协商 Range 后流式写盘，检查大小上限与短响应，周期性更新进度和检查点。
6. 释放下载网络额度，再将必要解密、验证、标签处理投给 processing 池。
7. 完成前最后检查取消；通过条件转换进入 finalizing，写发布意图。
8. 同文件系统重命名、记录资产并标记 completed，返回 file_id 与处理报告。

默认音频传输最大 2 GiB，单次传输空闲超时 30 秒、一次任务尝试最多 10 分钟；首次开始后任务绝对执行截止为 30 分钟。重启不会重置 deadline 或已消耗次数；已超出预算的任务明确失败。长期、慢速需求可调大预算，不能无限重试。

### 进度与完成

接收字节在内存中更新，公开／持久检查点最多每秒一次或重要状态转换时立即更新。公开快照 version 与可见进度同步递增，允许 ETag 条件轮询。总大小未知时返回 total_bytes=null，禁止伪造 100%；completed 是发布结果，不是仅网络接收完成。

文件已下载但标签 best_effort 失败时，任务完成且带 warnings；required 模式失败则不发布资产。写独立歌词也有完成结果，不能发起异步写入后立即宣称所有文件已经成功。

### SSE 事件传输

主通道为 SSE，每个前端复用一条订阅接收其 principal 的全部任务变化。普通进度默认每任务每秒最多一次，状态转换在持久提交后立即发布；只有已提交的公开版本才能通知。详情与恢复流程见 [API 9.4](api-contract.md#94-sse-下载事件)。

官方 [SSE 服务端示例](https://github.com/yhirose/cpp-httplib/blob/74ef3c42188acd6391f027c4337fb0e1a68c0024/example/ssesvr.cc) 使用 `set_chunked_content_provider`、`text/event-stream` 和 `DataSink`。这是阻塞式长响应，不是协程 I/O。每条订阅由事件 Server 工作线程发送；下载线程仅投递有界通知，不直接对慢客户端写 socket。

每订阅队列最多 128 个事件且编码后合计不超过 256 KiB，单事件最多 16 KiB。同任务尚未发送的进度可替换为较新版本；不能静默丢弃终态。超限或内部发布失败时标记需要重新同步并关闭受影响订阅，客户端重连查询事实状态。发布失败不得回滚已提交任务。任务状态以 SQLite 为准，首版不建立持久事件日志。

等待事件使用可唤醒的条件变量，默认每 15 秒发送 SSE 注释心跳，socket 写空闲超时 10 秒，单连接最多 30 分钟后正常断开重连。DataSink 写失败、客户端断开、身份撤销或服务退出时，注销订阅、释放队列和额度。撤销检查至少在心跳时执行；控制 API 的短请求总截止时间不套用到 SSE。所有订阅状态使用受控共享所有权，不捕获已销毁的 Request／Response。

事件流已发头后不追加 JSON 错误信封；关闭流后由客户端恢复。正常停机唤醒所有事件等待者并关闭订阅，再销毁事件分发器；退出不等待 30 分钟连接期限。心跳、限额、重连退避与慢消费者处理必须在实现阶段验证，不能照搬示例的简单广播器作为生产队列。

### 取消竞争

queued／waiting_retry 可立即转 canceled。运行阶段先持久记录 cancel_requested，并进入 canceling，然后取消当前请求或让工作在安全点退出；非可中断的标签库需要等待安全结束，不能从 UI 假装已终止。

进入 finalizing 的条件转换与取消命令由同一持久版本检查排序：取消先到则不能发布；finalizing 先到则取消返回 409 TASK_FINALIZING。completed 后取消也返回 409 TASK_TERMINAL，删除文件是另一种操作，首版不把取消隐含为删文件。

## 重试、换源和续传

| 失败 | 动作 |
| --- | --- |
| 瞬时连接中断／空闲超时 | 同一逻辑传输最多额外重试 2 次；退避 1 秒、2 秒并加抖动 |
| 429／上游 5xx | 可进入任务等待重试，尊重有上限的 Retry-After；默认最多 3 次逻辑尝试 |
| CDN 403／404／410 | 不盲目重复同一 URL；重新解析同一实际曲目，检查资源身份后再续传或重下 |
| 会员／凭证失效／能力不支持 | 返回业务错误，不用网络重试掩盖；auto 换源仅对明确允许的类别执行 |
| 磁盘不足／路径无权限／标签 required 失败 | 明确失败，等待用户处理后创建重试任务 |
| 用户取消 | 不重试、不自动换源 |

waiting_retry 释放执行线程与在途额度，next_retry_at 存 DB，由调度器到时重新领取，不能让下载工作线程 sleep 很久。

续传要求部分文件与资源身份匹配：优先使用强 ETag、可用的 Last-Modified／If-Range、总大小、平台文件 hash 和实际歌曲／品质。只有 URL 相同、文件名相同或时长相近不够可靠；证据不足就重下。

用户取消后清理未发布工作文件；失败工作文件默认最多保留 24 小时供诊断与受控检查，手动新建重试任务不承诺复用它。service_shutdown 与崩溃恢复所需工作文件依据活动任务及发布意图保留，不能套用终态清理规则删除。

请求 `Range: bytes=N-` 后严格核对 206 的 Content-Range 起点和总长；200 覆盖重下；416 仅在总长恰好等于已完成长度且身份与校验成立时进入完成验证，否则重新解析或重下。资源改变必须丢弃旧前缀，不能把不同品质或录音拼接。

换源在开始传输前确定实际曲目并记录；已经写入的字节不能继续拼接另一来源。若策略最终选择其他来源，必须使用新的工作资源身份与从零开始的字节流。

## 崩溃恢复与优雅退出

| 持久状态 | 启动恢复 |
| --- | --- |
| queued／waiting_retry | 保留队列或等待时刻，检查预算后继续 |
| resolving／probing | 清理旧进程租约，重做解析，保留尝试与预算 |
| downloading | 校验部分文件和检查点，重新解析并验证身份，续传或安全重下 |
| processing | 使用保留的传输完成文件重做处理；不在被半改写的文件上盲目继续 |
| finalizing | 根据 finalization_intent、文件存在性与证据补齐发布或报告恢复错误 |
| canceling | 完成清理后 canceled，不擅自恢复成可下载任务 |
| 终态 | 保留历史，懒检查对应文件存在性 |

恢复不重置预算，也不依赖旧签名 URL。正常停机先将 readiness 置失败、停止接收新任务与领取任务，再给在途工作最多 15 秒收尾；随后以 service_shutdown 原因请求停止、保存检查点、释放媒体流、关闭监听并等待可控工作退出，最后关闭 DB。

service_shutdown 与用户取消不同，保留可恢复工作；退出后服务管理器若强制终止，启动仍按上表恢复。取消请求不保证不支持中断的第三方代码能在 15 秒内返回，需在接入验证中排除无界操作，并由外部服务管理器设置最终停机上限。

## 媒体流桥接

httplib Client 没有可以直接拿来当通用异步流的原生协程契约。媒体桥接采用受限生产者／消费者：

```text
媒体上游池：建立请求 → 得到并校验最终响应头 → 写入有界字节缓冲
                                     │ headers-ready
媒体 Server：等待头部／错误 → 设置状态与 ContentProvider → 缓冲 → DataSink
```

每条播放流默认使用 256 KiB 缓冲上限，超过则阻塞生产者读取；缓冲耗尽时消费者有超时等待。内存预算还要计算库缓冲、TLS 和线程栈，不能只统计这 256 KiB。

必须在向下游提交头之前完成上游状态、Range 和有限刷新判断。不能先返回 200，再发现上游 403／416，却把错误页接进音频。请求中途失败、下游头已经提交时，只能终止流并记原因，不能再发一段 JSON 错误作为音频尾部。

在发头前发生 403 可重新解析同一录音一次，沿用请求 Range 并核对身份；无法确认一致性时返回 409 RESOURCE_CHANGED，要求新建会话。播放会话创建时的 auto fallback 不延伸为传输中的自动替曲。

文件发送直接从只读资产句柄按范围读取，不占媒体上游线程。所有 content provider、releaser 和上游 worker 共享受控会话状态；任一侧取消、断开或失败都唤醒另一侧并释放额度。详情见[API 媒体契约](api-contract.md)。

## 验证场景

优先验证：满负载媒体下控制请求仍受明确预算约束；多前端同时搜索不出现同池等待；取消实际终止请求；跨用户 Cookie 不串用；200／206／416 与资源变化不损坏文件；重启覆盖所有任务阶段；文件发布与 DB 崩溃窗口可恢复；慢消费者内存有界；过期票据不能创建新媒体请求。
