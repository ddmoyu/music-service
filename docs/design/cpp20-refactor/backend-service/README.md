# 音乐后端服务设计

更新：2026-10-24。本目录维护后端设计与接口契约；当前实现和验收范围见[功能状态](../../../feature-status.md)。账号启停、Cookie 自动校验和会员到期字段已接入，其他设计不能仅凭文档存在判定已实现。

本项目是纯后端，不包含 GUI。独立常驻进程 `music-service` 通过 HTTP 服务网页、Electron、Tauri、Qt、Win32 和 CLI 等外部客户端；必须支持跨平台与 Docker 部署，不依赖桌面会话或前端进程。principal 表示调用方身份，同一身份的多个客户端共享权限与任务。

## 核心决策

| 项目 | 方案 |
| --- | --- |
| 语言与构建 | C++20、CMake、CMakePresets；FetchContent 浅克隆、固定 tag 并校验 commit |
| 产品与平台 | 无 GUI 的跨平台后端；Windows／Linux 与 Docker 为必需目标，架构和支持级别以配置与部署为准 |
| 网络 | cpp-httplib Server／Client；Drogon 备选；阻塞 I/O 配合有界工作池 |
| 控制入口 | `127.0.0.1:17632`，`/api/v1` |
| 媒体入口 | `127.0.0.1:17633`，`/media/v1` |
| 事件入口 | `127.0.0.1:17634`，`/events/v1` |
| 入口隔离 | 同进程共享业务和数据库，各入口独立线程池；反向代理可统一 origin |
| 地址发现 | API 地址由部署配置或启动器交付；媒体／SSE 地址从 info 获取，禁止推算端口 |
| 下载 | 持久任务，提交后由后端执行，文件保存到后端 destination |
| 进度 | SSE 推送与独立 HTTP 查询共用任务快照 |
| 媒体访问 | 复用 asset_id／file_id，提供可选代理或受控直链 |
| 播放与客户端保存 | 前端管理播放器和本机保存；后端完成不代表客户端已落盘 |
| 持久化 | SQLite，单 writer 与受限读连接 |
| JSON | nlohmann/json 用于协议边界 |
| 音频 | 原始编码保存，标签可选，转码非必需 |
| 授权 | token 对应 principal，任务、文件、凭证按身份隔离 |
| 默认策略 | 仅同源下载、品质 strict、拒绝明确试听 |
| 音乐平台顺序 | 酷我先完成 S1；已研究平台由易到难，按需接入更多候选来源，不设固定平台数量上限，见[开发顺序](../platform-roadmap.md) |
| 平台扩展 | 开放 source + 独立能力 + ProviderBundle；全部原生实现，不用外部下载工具；目录与实际音频来源分别保留 |
| 待定／待验证 | 各平台端点与后续登录／签名细节、TLS／协议加密实现、标签覆盖 |

业务公共类型不暴露 httplib、JSON 或 SQLite 类型。S1 启用文件出口与必要票据；在线代理独立开关。平台、任务、文件和已解析音源分别使用 source/id、task_id、file_id、asset_id。

## 运行结构

见[系统总图](../architecture.md#图-1系统进程与部署边界)和[详细架构图](../architecture-details.md)。控制、媒体、SSE 是同一进程中的三个协议入口，各自拥有 HTTP 工作池，共享应用用例、身份和存储。持久下载由 Scheduler／Runner 执行，实际网络操作统一经过 runtime/admission；已提交的任务快照经有界 EventHub 通知客户端。

编译依赖与运行调用分图表达：application 通过自身端口调用外部实现，具体实例由 src/server 组装；Provider 和 HTTP 适配器不拥有第二套任务状态或持久队列。

## 功能分期

阶段顺序、完成条件和验收责任以[开发任务清单](../development-tasks.md#总体顺序与交付关口)为唯一维护位置。本页只概述范围：S0 基础服务、S1 酷我闭环、S2 平台与目录扩展、S3 可靠性、S4 在线媒体、S5 部署发布。平台扩展不要求全部来源完成，第二平台关口可替换具体来源。

S1 已包含最小安全发布与重启处理；S3 扩展故障覆盖。服务功能通过 info 声明，平台能力通过 providers 声明，未启用／不支持分别返回 501／422。

模块审查 R1～R4 已写入规范：下载意图与复用规则、统一账号身份、平台授权工厂、任务调度与上游入场边界。具体变更及分期验收见[审查结论](module-boundary-review.md#本轮模块与功能拆分审查)；文档闭合不代表相应代码已实现。

S1 即建立扩展契约并用酷我验证；S2 通过第二个真实平台及模拟目录源验证无需修改公共业务代码；之后的平台同样原生接入。平台总数不受单次搜索来源上限约束，目录型来源无需伪装提供同源音频。跨平台匹配与换源已取消，目录源不提供音频时明确返回能力不支持。

跨平台与容器兼容属于 S0 起的持续约束，S5 完成部署集成与发布验证。系统、CPU 架构、运行库与部署形态分别记录，只有经过验证的组合才声明正式支持，见[配置与部署](configuration-and-deployment.md)。

首版范围外：播放器内核、跨设备播放同步、完整后台歌单枚举、用户注册、分布式调度、共享数据库多副本、通用转码集群、HLS 和任意 URL 代理。
