# 实施计划与验证

功能交付按[设计入口 S0～S5](backend-service/README.md#功能分期)推进；下面列出验证顺序。构建遵守 [C++20／CMake／FetchContent 规则](backend-service/build-and-dependencies.md)。

## 验证顺序

| 步骤 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 平台范围 | 确认首批平台、能力、凭证和协议算法，整理去凭证样本 | 迁移清单、算法清单和离线样本齐全 |
| 2 网络与 TLS | 验证 cpp-httplib Server／Client、线程池、证书、流式传输 | 控制／媒体／SSE 隔离，超时取消有效，内存有界 |
| 3 协议迁移 | 迁移签名、请求、解析和错误；先完成一个平台 | 搜索、详情与音源解析形成闭环，账号条件明确 |
| 4 集合与聚合 | 歌单、专辑、分类、榜单、歌词、多源搜索 | 逐源分页、部分失败和目录来源表达正确 |
| 5 任务与资源 | 持久下载、SSE／HTTP、取消重试、续传、恢复、匹配 | 关闭前端后任务继续，恢复不损坏文件，错误版本不替换 |
| 6 文件处理 | 验证 MP3／FLAC／M4A 标签、封面、歌词和必要解密 | 格式覆盖明确，载荷保真，失败遵守策略 |
| 7 发布 | 固定依赖与功能组合，验证目标环境 | 干净目录可启动，依赖完整，正常退出，持久数据可恢复 |

网络主方案有明确缺口或调优后仍不满足目标时，评估 Drogon。TLS 先验证 httplib 支持的组合；若 Schannel 成为硬要求，单独验证出站 curl，不因此更换 Server。

## 网络检查

| 场景 | 检查项 |
| --- | --- |
| 基础服务 | 无界面启动、健康、JSON、并发、正常退出 |
| 入口隔离 | 媒体／SSE 满额和慢消费者下控制请求仍可处理 |
| 地址发现 | 固定端口冲突报错；桌面动态端口经启动器交付；info 公布实际地址 |
| 上游 | HTTPS GET／POST、UA、Referer、Cookie、预算与取消 |
| TLS | 正确证书通过，错误证书链／主机名拒绝 |
| 重定向 | 次数、每跳地址校验、敏感头传播 |
| 字节传输 | 分块写盘、断流、背压、稳定内存与资源释放 |
| Range | 206 校验、200 重下、416、资源变化 |
| 独立客户端 | 若引入 curl／cofetch，验证线程归属、生命周期与停机 |

记录发布目录总大小（含 DLL、证书和资源）、并发内存、线程数和延迟，按目标设备调整配额。

## 文件与恢复检查

- 标签验证覆盖重复写入、未知标签保留、错误回退和临时空间。
- 容器格式比较音频载荷，不仅比较整文件哈希；检查目标播放器可读性。
- 检测／解码工具可只用于验证环境，无需随产品分发。
- 不支持的标签格式按策略保留音频、输出侧文件或使用明确启用的工具。
- 验证幂等、真实取消、Range 资源一致性及发布意图恢复。
- 匹配样本包含同名、翻唱、现场、Remix、资源失效和试听。

完整行为用例见[流程与验收](backend-service/flows-and-acceptance.md)。

## 发布与测试层次

| 层次 | 对象 |
| --- | --- |
| 领域／协议 | 固定签名向量、响应解析、品质、版本匹配、状态转换、去重与文件名 |
| 本地集成 | 模拟上游、Cookie、超时、重定向、Range、取消、慢消费者、DB 与文件故障 |
| 文件 | 格式、标签、封面／歌词、重复处理、载荷保真 |
| 在线 | 实际平台、当前账号与品质条件 |
| 目标部署 | Windows，计划支持的 Linux／NAS 架构；端口、权限、持久卷、启停和依赖 |

先发布独立服务，再接入网页、CLI 或桌面外壳。旧页面兼容、音乐库扩展和跨端同步单独排期。优先验证文件损坏、误匹配和无界资源路径，不为纯转发层重复编写测试。

待定：首批平台与登录／签名范围、TLS 后端、首批格式和标签库、可选 FFmpeg、首个前端、链接方式和目标平台。结论写回对应规范。
