# 实施计划与验证

更新：2026-10-20。功能交付按[任务清单 S0～S5](development-tasks.md#总体顺序与交付关口)推进。具体开发事项、直接依赖和验收责任以[开发任务拆分](development-tasks.md)为实施清单；本文保留阶段验证策略。构建遵守 [C++20／CMake／FetchContent 规则](backend-service/build-and-dependencies.md)。

本项目是纯后端，无 GUI；跨平台与 Docker 是持续约束。S0 即验证 Windows／Linux 无界面构建和最小容器启动，S5 完成系统服务、多架构与部署发布，不把平台适配全部推迟至最后。操作系统、CPU 与发布边界以[部署矩阵](backend-service/configuration-and-deployment.md#部署方式)为准。

平台优先顺序只在[平台路线图](platform-roadmap.md)维护。酷我先完成产品闭环，第二个真实平台经 T41 验证扩展机制后再推进海外目录；单个来源受阻不改变其他来源的技术可行性。

S0／S1 完成[平台扩展基线](backend-service/provider-extensibility.md)：开放 source 标识、能力组合、ProviderBundle 注册与酷我；模拟契约覆盖目录型来源。S2 用第二个平台和 Spotify 验证复用边界，后续平台同样原生接入。目录跨源下载归 S4 的匹配与显式策略，不能在平台内部隐藏换源。

实现前以[已补齐的模块审查](backend-service/module-boundary-review.md#本轮模块与功能拆分审查)为基线：下载按 NormalizedDownloadIntent 去重，账号以 AccountBinding／AuthIdentityKey 分别表达稳定选择和授权快照，平台授权协议随 bundle 注册，runtime/admission 统一分配上游额度。验收编号 A35～A46 及其分期以[流程与验收](backend-service/flows-and-acceptance.md#8-验证层次与实施关口)为准；这些是设计和验收要求，当前没有对应实现。

## 验证顺序

阶段完成条件、直接／可选依赖和验收责任见[任务清单](development-tasks.md#总体顺序与交付关口)，本文不重复阶段表。S1 的安全发布、取消和预算属于首版必需能力；复杂处理和匹配按后续任务交付。下面保留跨阶段的验证方法。

网络主方案有明确缺口或调优后仍不满足目标时，评估 Drogon。TLS 先验证 httplib 支持且覆盖目标系统的组合；若 Windows 部署需要 Schannel，单独验证出站 curl，同时保留 Linux／容器的对应实现，不因此更换 Server。

## 网络检查

| 场景 | 检查项 |
| --- | --- |
| 基础服务 | 无界面启动、健康、JSON、并发、正常退出 |
| 入口隔离 | 媒体／SSE 满额和慢消费者下控制请求仍可处理 |
| 地址发现 | 固定端口冲突报错；桌面动态端口经启动器交付；info 公布实际地址 |
| 上游 | HTTPS GET／POST、UA、Referer、Cookie、预算与取消 |
| TLS | 正确证书通过，错误证书链／主机名拒绝 |
| 重定向 | 次数、每跳地址校验、敏感头传播 |
| 字节传输 | 分块写盘、断流、背压、稳定内存与资源释放 |
| Range | 206 校验、200 重下、416、资源变化 |
| 独立客户端 | 若引入 curl／cofetch，验证线程归属、生命周期与停机 |

记录发布目录总大小（含 DLL、证书和资源）、并发内存、线程数和延迟，按目标设备调整配额。

## 文件与恢复检查

- 标签验证覆盖重复写入、未知标签保留、错误回退和临时空间。
- 容器格式比较音频载荷，不仅比较整文件哈希；检查目标播放器可读性。
- 检测／解码工具可只用于验证环境，无需随产品分发。
- 不支持的标签格式按策略保留音频、输出侧文件或使用明确启用的工具。
- 验证幂等、真实取消、Range 资源一致性及发布意图恢复。
- 匹配样本包含同名、翻唱、现场、Remix、资源失效和试听。

完整行为用例见[流程与验收](backend-service/flows-and-acceptance.md)。

## 发布与测试层次

| 层次 | 对象 |
| --- | --- |
| 领域／协议 | 固定签名向量、响应解析、品质、版本匹配、状态转换、去重与文件名 |
| 本地集成 | 模拟上游、多凭证类型与隔离、超时、重定向、Range、取消、慢消费者、DB 与文件故障；平台契约与 100 源发现 |
| 文件 | 格式、标签、封面／歌词、重复处理、载荷保真 |
| 在线 | 实际平台、当前账号与品质条件 |
| 目标部署 | 按部署矩阵验证系统／架构／运行库、Windows 服务、Linux 系统服务、NAS 与 Docker／Compose；覆盖路径、证书、权限、持久卷、停止信号和依赖 |

先发布独立服务，再接入网页、CLI 或桌面外壳。旧页面兼容、音乐库扩展和跨端同步单独排期。优先验证文件损坏、误匹配和无界资源路径，不为纯转发层重复编写测试。

音乐平台顺序与首次接入范围已确定，见[平台开发顺序](platform-roadmap.md)。各平台端点与签名向量、后续授权、TLS／协议加密、格式与标签库、可选工具、链接方式、最低系统／运行库和发布组合的验证责任，已分配至[任务清单的待验证事项](development-tasks.md#待验证事项与完成定义)。macOS 等候选目标单独明确；外部前端由单独项目维护，不是本项目交付前置条件。结论写回对应规范。
