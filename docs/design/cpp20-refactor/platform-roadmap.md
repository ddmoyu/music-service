# 音乐平台开发顺序

更新：2026-10-23。已提交基线为 0.1.6（`e13053c`），当前应用版本以根目录 CMakeLists 为准。酷我、5sing、网易云已完成上一轮批准的功能补齐；QQ 音乐、酷狗与咪咕已完成下述 Windows 首阶段验收，代码尚未提交。用户确认国内平台按 **QQ 音乐 → 酷狗 → 咪咕** 接入，优先推荐、排行榜及单曲／歌单／专辑搜索；**Windows 优先，其他操作系统与部署环境的专门适配、验收放到最后**。各平台的目标清单与实际验收范围分别记录。

## 排序口径

本轮以用户指定的国内平台和发现、搜索功能为优先级，同一平台按“发现／搜索 → 集合详情／曲目 → 下载闭环”交付。优先复用公共 Provider、目录、分页、凭证、任务和文件出口。下方历史研究的难度只用于估计工作量，不再决定当前实施顺序，也不证明接口当前可用。

既有国内平台批次为 QQ 音乐、酷狗、咪咕。2026-10-23 用户追加启动并完善 Jamendo：按 N01 实现 20 项匿名能力，新增用户确认范围内的官方精选歌单搜索、原生歌曲分类及官方歌曲榜，并核查音质，逐项结果见 [Jamendo 验收](../../research/jamendo-acceptance.md)。其他平台候选按各自后续任务安排，跨平台匹配与换源已取消。NCM 真实文件和网易云 Hi-Res 样本验证保留待验收状态，缺少样本不阻塞新平台。

平台可按目录、搜索、链接解析、歌词或音源能力独立接入。所有平台都由本项目原生解析与下载，不使用外部下载工具或第三方解析服务，见[多平台扩展设计](backend-service/provider-extensibility.md)；数量不限不等于单次请求无限并发。

0.1.8 按用户追加要求补齐酷我歌手搜索、详情、歌曲／专辑分页和专辑封面，已完成 Windows 在线验收；详见[验收记录](../../research/kuwo-artists-acceptance.md)。后续新平台仍按以下顺序。

### 每个平台的功能与验收清单

| 子项 | 实现范围 | 验收标准 |
| --- | --- | --- |
| 发现 | 平台公共推荐歌单、分类及分类歌单；优先匿名可用入口，个性化每日推荐单列，不混为公共推荐 | 真实推荐项可读取详情与曲目；保留平台返回顺序；若分类为本地内置或由搜索派生，显式标明 catalog_kind；不以搜索结果或排行榜冒充推荐 |
| 排行榜 | 榜单列表、详情、榜单歌曲，平台提供时保留期次／更新时间 | 至少两个有效榜单可读取；曲目排名、顺序及分页一致；失效榜单明确报错，不返回空成功占位 |
| 单曲搜索 | 中文／英文关键词搜索、分页、歌曲详情，保留稳定平台标识 | 有结果的关键词可搜索；可分页集合验证至少两页；空结果、非法参数、超时、限流、登录限制有明确结果；歌曲可继续解析音源 |
| 歌单搜索与曲目 | 歌单搜索、详情、分页曲目；分类与推荐结果复用相同实体 | 搜索项与详情 ID 一致；完整遍历无意外遗漏，保留重复位置；平台声明总数、实际可见曲目及不可用项分开报告 |
| 专辑搜索与曲目 | 专辑搜索、详情、分页曲目、歌手／发行日期／封面／曲目编号等真实字段 | 搜索到的专辑可打开并遍历歌曲；编号来自专辑字段，不根据搜索顺序伪造；未知字段保留未知 |
| 歌手目录 | 在核心三类搜索与发现完成后补歌手搜索、歌曲及专辑列表，按平台实际端点覆盖 | 歌手身份不与歌曲或专辑混淆；热门歌曲和完整目录明确区分；没有经过验证的能力不注册 |
| 链接与元数据 | 单曲／歌单／专辑链接，歌词、封面及既有标签和独立文件输出 | 合法链接解析到正确实体，拒绝伪造主机及歧义 ID；歌词／封面确实对应歌曲，缺失明确报告；嵌入和独立导出策略仍相互独立 |
| 下载与权限 | 标准品质优先，复用取消、重试、有限批次、复用及恢复；Cookie 仅在需要时接既有凭证接口 | 每平台至少一首有权限的整曲完成真实下载、内容验证和重启回读；试听不冒充整曲，实际文件品质符合 strict／allow_lower 规则；高品质、加密音源分别验收 |

以上是三个平台的目标清单，并非上游能力保证。端点准备阶段必须先记录匿名／Cookie 条件、签名及分页样本；找不到可用端点或必要账号时保留具体缺项，不以第三方工具、空数组或静态伪数据替代。缺少某项账号样本时继续推进可独立完成的公开接口，不能据此宣称整个平台全部完成。扫码登录不纳入本轮，网易云扫码继续明确排除。

### 首阶段：QQ 音乐

1. **协议准备**：确认推荐、榜单与三类搜索的实际 HTTPS 端点；整理请求、响应、字段、错误、匿名／Cookie 要求及分页边界。保留脱敏或受控样本，生产仍使用原生 C++。
2. **目录能力**：完成上述发现、榜单及三类搜索，并接通各类详情和曲目列表；复用公共路由、鉴权、限流、缓存与身份绑定游标，不新增 QQ 专用队列或数据库。
3. **下载衔接**：补链接、歌词、封面、音源与真实品质判断；对已搜索或发现的曲目完成下载、复用和重启回读。
4. **Windows 验收**：MSVC x64 构建、相关单元／集成用例和真实 HTTP 联调；报告逐项能力状态、测试结果及账号限制后进入酷狗。账号或单个端点受阻时记录缺项，可先推进下一平台的公开目录能力。

参考核对基线为 `guohuiyuan/music-lib@6353508e84cd357b5bc3acf32d95a16e01bbe20c`。其中 QQ、酷狗有独立推荐函数和榜单／三类搜索入口；该参考版本的咪咕分类为内置标签配合搜索派生。本项目咪咕已改用实测可用的官网分类与公共推荐端点，见下方 N08 验收。参考函数存在只证明参考项目的代码路径，不作为本项目实现或当前端点可用的证据。

## N05 酷狗首阶段验收（2026-10-23）

酷狗协议包 0.1.10 已接入 17 项匿名能力。Windows MSVC x64 Debug 构建、23 项离线协议测试，以及真实推荐／分类／榜单、三类搜索、集合遍历、标准整曲下载、标签与侧文件、复用和重启回读均已完成，详见[酷狗接入验收](../../research/kugou-acceptance.md)。线上验证包括 55 个榜单、76 首歌单和 45 首专辑完整遍历。

公共曲目身份使用标准品质 hash，高品质与无损候选由同一歌曲详情重新核对。付费无音源明确返回权限错误，试听不能冒充整曲；本轮无需 Tracker 备用路径。高品质／无损候选逻辑已离线验证，成功下载仍待可访问样本。Cookie、个人歌单、Hi-Res 与加密音源未接入。

按用户随后要求，0.1.17 新增歌手搜索、详情、歌曲与专辑分页，总计 21 项匿名能力。歌手搜索使用官网公开签名的真正分页接口；已完整遍历薛之谦目录 963 个歌曲位置（961 个不同 hash）和 47 张专辑，并从贝瓦儿歌目录完成标准整曲下载、复用与重启回读。审查修复备注误作专辑名、分页上限误报结束、加密候选阻断显式降级三处问题，37 项离线用例通过；详细证据见[酷狗验收记录](../../research/kugou-acceptance.md)。

18 项原生能力已接入，详见[适配器](../../../src/providers/migu/README.md)与[验收记录](../../research/migu-acceptance.md)。Windows MSVC x64 Debug 独立五平台构建通过；咪咕专项 19 项／747 条断言通过，全量 CTest 440 项中 434 通过、6 跳过、0 失败。

| 9 | 网易云 `netease` | 高 | 原生迁移需逐端点选择 Linux／EAPI／WeAPI 包装，处理 MD5、AES、部分路径的 RSA、Cookie、权限和品质映射。先迁移闭环必需协议并用固定向量核验，再扩展其他包装和个人化能力。依据：[协议算法][netease-crypto]、[取流][netease-download]、[SDK 核验](../../research/lanyue/npm-sdks.md)。 |
| 10 | 咪咕 `migu` | 高 | 搜索并不复杂，但计划覆盖的取流有多资源标识、重定向、品质候选与加密音频；需把 FileKey、解密、格式验证纳入文件处理。明文标准品质可先完成，但不能据此标记全部品质已支持。依据：[取流与音频解密][migu-download]。 |

难度接近的平台仍可能因当前账号、地区或接口变动而改变实际工期。单个平台无法完成在线验证时，保留原因和样本缺口，按本页当前执行顺序推进其他可独立完成的工作；不能将阻塞平台标为支持。

## 开放扩展清单

后续平台仍须完成“搜索／链接 → 完整音频下载”的验收；跨平台匹配、手动与自动换源已于 2026-10-24 取消，不再排期。

| 后续候选 | 接入目标 | 进入实施前的检查 |
| --- | --- | --- |
| YouTube／YouTube Music `youtube` | 原生解析独立音轨 | 播放器脚本的签名与 n 参数需自行实现并持续跟进变更，难度高；稳定视频身份、实际音轨与品质、凭证、过期地址；分段流另验证 |
| SoundCloud `soundcloud` | 搜索／链接、曲目和集合、已验证的音源能力 | 官方接口的账号要求、分页与实际传输形态 |
| Bandcamp `bandcamp` | 曲目／专辑链接、元信息和可用音频 | 整曲／试听、具体可下载资源与格式；不假定存在全站搜索能力 |
| Audius `audius` | 曲目／歌单／作者及音源，使用原生 API | 接口鉴权、分页、节点／地址变化及目标环境传输 |
| 其他来源 | 持续加入候选，每个平台按已实现能力开放 | 优先 API／协议明确、可复用公共传输且可提供稳定样本的来源，不设最终封闭清单 |

每个新来源需单独建立原生 descriptor、能力样本和验证状态，不通过一个通用下载入口宣称支持全部站点。

## 与服务分期的关系

平台顺序与 S0～S5 是两个维度；不要求完成全部平台才交付某个服务阶段，也不要求补齐某个平台的全部功能才接入下一平台。

本页是平台优先顺序的唯一维护位置。具体任务、技术前置和逐平台验收见[开发任务拆分](development-tasks.md#后续平台任务)。第二平台关口 T41 已选用 5sing 完成本机验收；YouTube 和其他开放来源仍在后续计划中。

平台可以先交付目录、解析或歌词，再补音源与其他能力；服务阶段的范围、完成条件和精确前置统一见[任务关口](development-tasks.md#总体顺序与交付关口)，本页不另列阶段表。所有平台持续验证声明的运行环境，发布组合按部署矩阵管理。

## 每个平台的完成条件

实施步骤与责任归属见[平台任务模板](development-tasks.md#单个平台的任务模板)，具体扩展行为见[扩展验收](backend-service/provider-extensibility.md#9-新平台交付模板与验收)。协议包通过只证明协议能力；产品声明还需要对应集成关口。酷我协议在 T12 验证，下载、恢复和文件获取在 T20 验证，不能相互作为前置。

首次能力、品质与算法范围以本页的平台行说明为准；未知或未验证能力保持未声明。默认品质与试听策略引用[公共模型](backend-service/data-models.md#品质解析和探测)，不沿用参考实现的静默降级或试听成功逻辑。

## 配套算法的接入顺序

已有 HTTP／TLS、JSON、摘要和 AES 等基础能力继续复用。QQ、酷狗、咪咕各自按已核实端点实现必要签名、编码及音频处理；不把 Jamendo、千千或其他后排平台作为算法准备前置。算法按实际端点清单接入，TLS 与协议加密职责仍分别管理。
